# DSH 技能市场插件（Skills Hub）开发方案

> 版本：v1 草案
> 日期：2026-10-12
> 参考实现：`reference/dsh-web/packages/dsh-skill-explorer`（`@linxin666/dsh-client-ui-skill-explorer` v0.4.6，BSD-3-Clause）
> 目标运行环境：DeepSeek Harness Web GUI，SDK cohort `0.2.0-rc.2`，宿主 `http://127.0.0.1:19387`

---

## 0. 一句话方案

做一个 **host/client 双半区**的 DSH 插件：client 半区往 `sidebar.panellist` 贡献一个「技能中心」行、往 keyed `main` 槽贡献中栏页面；host 半区提供一条 loopback 围栏的 `/api/skills-hub/*` 路由族，负责**网络技能检索**、**安全下载安装**、**本地技能扫描管理**与**新建技能**。

参考项目只能管本地已有的技能；本方案补上它缺的核心一环——**技能市场（搜索 → 预览 → 安装 → 更新/卸载）**。

## 2. 调研结论（已实测，非推测）

### 2.1 参考插件的形态（可直接沿用）

`packages/dsh-skill-explorer` 是本方案的骨架模板：

- **包形态**：`type: module`，`main: lib/index.js`，`exports` 提供 `.`（host 半区）与 `./client`（浏览器半区）；`package.json` 里 `dsh.bundle.patch` 指向 `cordis.patch.yml`，`dsh.client = { inject: [...], platform: "web" }`。
- **激活方式**：`cordis.patch.yml` 只写一行 `- insert: [{ id, name }]`，`name` 必须**恰好等于包名**（官方 `dsh-client-modules` 只把浏览器半区挂在说明符等于包名的那一行上）。
- **host 半区**（`src/index.ts`）：`inject = ['webServer', 'skills', 'sessions']`，用 `ctx.webServer.register(route)` 注册路由，`mountOnce()` 防双源重复注册。
- **client 半区**（`src/client/index.ts`）：`inject = ['slots', 'locale', 'layout']`，注册 i18n 字典 + 通过 `ctx.slots.inject(...)` 注册两个座位。

### 2.2 侧边栏入口的确切机制（已用 Inspect 验证）

`sidebar.panellist`（list，root 作用域，"Global panel icons"）：

| 字段 | 类型 | 必填 | 含义 |
|------|------|------|------|
| `id` | string | 是 | 你自己的 cell key，**同时被 `main` 槽用作 dispatch key** |
| `order` | number | 否 | 升序排位 |
| `label` | string \| (() => string) | 否 | 显示文本；thunk 每次投影读取，**可跟随语言切换** |

当前占位者：`plugins`(order 0)、`schedules`(order 10)；参考项目 skill-explorer 用 **order 30**。本方案建议 **order 40**。

`main`（keyed，root 作用域，"Central panel selected by sidebar entry id"）：注册 `{ name: 'main', key: <id> }`，布局只在该面板被选中时挂载页面。已占用 key：`conversation`、`plugins`、`schedules`。

> 关键点：**行盒、标签、高亮、折叠轨道、面板切换全部归 shell**，插件只画图标与页面。这与"自己 DOM 接管中栏"的旧写法完全不同，必须走这两个座位。

### 2.3 网络技能数据源（已实测可用）

| 数据源 | 端点 | 实测结果 | 用途 |
|--------|------|----------|------|
| **skills.sh**（Agent Skills 官方注册中心，agentskills.io 标准） | `GET https://skills.sh/api/search?q=<q>&limit=<n>` | 200，返回 `{count, skills:[{id, source, skillId, name, installs}]}` | 主搜索源 |
| GitHub Contents API | `GET /repos/{owner}/{repo}/contents/{path}` | 200 | 枚举某仓库下的技能目录 |
| GitHub Git Trees API | `GET /repos/{owner}/{repo}/git/trees/{ref}?recursive=1` | 200 | 一次性拿全仓库文件树（安装清单） |
| raw 文件下载 | `https://raw.githubusercontent.com/{owner}/{repo}/{ref}/{path}` | 200 | 下载 SKILL.md 与附属文件 |
| **GitHub 加速节点** | 形如 `https://gh-proxy.com/https://raw.githubusercontent.com/...` | 200，**701ms（实测最快）** | 国内直连不可用时的兜底 |
| `dsh-market.com` | `/manifest/{skins,pets,presets,plugins}.json` | 200；**`skills.json` 404** | 目前无技能清单，留作后续适配位 |
| `anthropics/skills` 仓库 | 顶层共 19 个技能目录 | 200 | 内置推荐源 |

**实测的加速节点可用性**（2026-10-12，`raw` 路径 1 次探测）：

| 节点 | 结果 | 耗时 |
|------|------|------|
| `gh-proxy.com` | OK | **701 ms** |
| `ghproxy.icu` | OK | 1269 ms |
| `ghfast.top` | OK | 1941 ms |
| `github.tbap.top` | OK | 2774 ms |

> 加速节点清单来自 `github.akams.cn` 前端硬编码数组（共 80+ 条，含 `search`/`contribute` 两类标签）。方案里做成**可配置的有序候选列表 + 逐个降级**，不硬编码单点。

**单技能坐标模型**（三个源统一抽象）：

```

  id: '<owner>/<repo>/<skillId>',
  repo: { owner, repo, ref },
  path: 'skills/pdf',            // 仓库内技能目录
  name: 'pdf', description: '...', installs: 209208 }
```

### 2.4 官方技能根约定（写路由必须遵守）

| 来源等级 | 路径 | rank（小者胜） |
|----------|------|----------------|
| `project-dsh` | `<projectRoot>/.dsh/skills` | 100 |
| `project-agents` | `<projectRoot>/.agents/skills` | 200 |
| `runtime` | 注册表 | 250 |
| `custom` | `customSkillDirs` | 300 |
| `user-dsh` | `$DSH_HOME/skills`（即 `~/.dsh/skills`） | 400 |
| `user-agents` | `~/.agents/skills` | 500 |
| `bundled` | 随包 | 600 |

- 技能名文法：`/^[a-z0-9]+(?:-[a-z0-9]+)*$/`（小写字母数字，单连字符连接，不可首尾/连续连字符）。
- 一个技能目录必须含 `SKILL.md`，frontmatter 必须声明**非空** `name` 与 `description`，否则官方 provider 直接丢弃——面板**不应展示模型收不到的技能**。
- 项目根 = 从 `cwd` 向上找最近的含 `.git` 的祖先目录。
- `findProjectRoot` / `userSkillRoot` / `projectSkillRoot` 在参考项目 `src/collect.ts:201,607,612` 已有实现，可直接移植。

### 2.5 三个必须遵守的硬约束（踩坑成本极高）

1. **客户端 bundle 纯净门**：浏览器 bundle 里 `@deepseek-ai/*` **只能 type-only import**。可以外部化（external）的模块白名单是宿主的冻结模块表：
   ```
   react, react/jsx-runtime, react-dom, react-dom/client,
   @deepseek-ai/cordis,
   @deepseek-ai/dsh-client-store,
   @deepseek-ai/dsh-client-ui-slots,
   @deepseek-ai/dsh-client-ui-primitives,
   @deepseek-ai/dsh-client-ui-dockkit
   ```
   跨插件协作**只能走 cordis 服务或 slot**，不能用 value import。
2. **API 路径必须文档相对**（不带前导 `/`）。宿主用 `<base href="./">` 提供 GUI，根绝对 `/api/...` 会在子路径部署下逃逸前缀导致 404（参考项目 issue #1707）。正确写法：`'api/skills-hub/list'`。
3. **行 id 是 loader 全局 id 空间**。同名 id 后来者胜且**不报错**，会静默丢掉官方行、连带其 UI 消失。必须用独占 id，`name` 字段必须正好等于包名。

| 项 | 状态 |
|----|------|

### 3.2 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 独立包 vs 在 dsh-web monorepo 内 | **独立包**（自带 tsdown 配置） | `dsh plugin add link:<绝对路径>` 即可安装，不要求用户 clone 整个 monorepo；发布也独立 |
| 与 skill-explorer 的关系 | **不依赖、不冲突**：移植其本地管理层代码思路，用独立面板 id 与路由前缀 | 两个插件可共存；技能中心页签不同行、不同 key |
| 面板 id | `skills-hub` | 不与官方 `plugins`/`schedules`/`conversation` 及 skill-explorer 冲突 |
| 行 order | 40 | 排在 plugins(0) / schedules(10) / skill-explorer(30) 之后 |
| 路由前缀 | `/api/skills-hub` | 独占命名空间 |
| 网络请求位置 | **全部在 host 半区** | 浏览器受同源/CORS 限制；且安全策略必须由 host 强制执行 |
| 客户端信任边界 | 客户端只发**身份**（id/name/path），**从不发 URL 与文件清单** | 防止任意路径读写与 SSRF |
| 安装目标默认根 | 用户根 `$DSH_HOME/skills/<name>/`，可选项目根 | 与官方 rank 语义一致 |

## 4. 网络检索层设计

### 4.1 统一的源适配器接口

```ts
// src/market/sources/types.ts
export interface MarketSkill {
  /** 全局唯一坐标，如 'anthropics/skills/pdf' */
  id: string
  name: string
  description: string
  /** 展示用来源，如 'anthropics/skills' */
  sourceLabel: string
  /** 详情/安装所需的仓库坐标 */
  origin: { kind: 'github'; owner: string; repo: string; ref: string; dir: string }
  installs?: number
  license?: string
  /** 该条来自哪个适配器 */
  provider: string
}

export interface MarketSource {
  readonly name: string
  /** 关键词检索（空串 = 榜单/推荐） */
  search(query: string, opts: { limit: number; signal: AbortSignal }): Promise<MarketSkill[]>
  /** 列出某仓库下全部技能（用于「按仓库浏览」） */
  listRepo?(coords: { owner: string; repo: string; ref?: string }, signal: AbortSignal): Promise<MarketSkill[]>
  /** 取技能元数据 + SKILL.md 正文（详情预览） */
  detail(skill: MarketSkill, signal: AbortSignal): Promise<{ markdown: string; files: string[] }>
}
```

### 4.2 适配器实现清单

**A. `skills-sh`（主源）**

```
GET https://skills.sh/api/search?q=<query>&limit=<n>
→ { count, skills: [{ id: "anthropics/skills/pdf", source: "anthropics/skills",
                      skillId: "pdf", name: "pdf", installs: 209208 }] }
```

把 `source`（`owner/repo`）+ `skillId` 解析成 `origin`。`description` 需二次拉取 SKILL.md frontmatter 补全（列表接口不带）。

**B. `github`（按仓库浏览 / 直连坐标）**

- 输入 `owner/repo[/子路径]` 或完整 GitHub URL。
- 用 Contents API 枚举目录；目录内存在 `SKILL.md` 即判定为技能。
- 详情用 raw 下载 SKILL.md，解析 frontmatter。

**C. `registry`（可配置的清单源）**

允许用户在设置里加 JSON 清单 URL（形如 `https://…/skills.json`，结构 `{ items: [{ id, name, description, repo, dir }] }`）。用于接入自建/社区技能索引，也为将来 `dsh-market.com/manifest/skills.json` 预留。

**D. `local`（离线导入）**

从本地 zip / 目录导入技能（走文件选择 + host 校验），满足无网环境。

### 4.3 GitHub 加速降级链

```ts
// src/market/proxy.ts
const DEFAULT_PROXIES = [
  '',                                  // 直连优先
  'https://gh-proxy.com/',
  'https://ghproxy.icu/',
  'https://ghfast.top/',
  'https://github.tbap.top/',
  'https://gh.dpik.top/',
]
export function proxiedUrl(url: string, proxy: string): string {
  return proxy === '' ? url : proxy + url
}
```

- 逐个候选尝试，首个成功即返回；记录最近成功节点（会话内缓存），下次优先。
- 全部失败 → 返回明确错误 `proxy-unavailable`，UI 提示可在设置里自定义节点。
- 用户可在插件 config 里覆盖 `githubProxies: string[]`。

## 5. 安装引擎设计（安全模型是重点）

### 5.1 安装流程

```
1. 客户端 POST api/skills-hub/install { id, target: 'user'|'project', cwd?, force? }
2. host 校验 id 形状（禁止任意 URL）
3. host 从源适配器重建该 id 的 origin（只信自己拉的元数据）
4. host 取仓库文件树 → 过滤出该技能目录下的全部文件 → 生成下载计划
5. 逐条校验 rel 路径（白名单正则 + 禁 '..' / 绝对路径 / 空段）
6. 下载到 目标目录同级 的临时目录 <dest>.install-<ts>-<rand>/
   - manifest ≤ 1 MiB，单文件 ≤ 8 MiB，文件数 ≤ 500，每次 fetch 30s 超时
   - 流式累计字节，超限立即 abort
7. 校验：临时目录内必须有 SKILL.md，且 frontmatter 的 name 合法、非空
8. 写 provenance（skills-hub.provenance.json：来源、坐标、ref、时间、每文件 sha256）
9. 目标已存在且未 force → 409 conflict；否则 rmSync 旧目录 + renameSync 原子落位
10. 失败路径：删除临时目录，目标目录保持原样（绝不留半成品）
```

### 5.2 安全要点

- **客户端从不发 URL / 文件清单**，只发全局 id；下载 URL 全部由 host 重建。
- **路径白名单**：`/^[A-Za-z0-9._][A-Za-z0-9._\-/]{0,199}$/`，且不含 `..`、`//`、不以 `/` 开头/结尾。
- **大小与数量上限**，防止恶意清单耗尽内存/磁盘。
- **硬超时**，防止挂死。
- **原子落盘**：临时目录 + rename，参考 `dsh-market/src/core/installer.ts`（Windows 下 rename 有短暂句柄释放问题，需带一次重试）。
- **provenance 记录**才能区分"市场安装"与"手工放置"，也是"检查更新/卸载"的依据。
- **写路由只信任最新扫描结果**：删除/编辑请求里的 `path` 只是身份声明，host 必须重新扫描确认同名同路径才动手（参考项目 `resolveScannedSkill`）。
- **符号链接技能拒删拒改**（会越出技能根）。
- **信任围栏**：loopback 套接字 + Host 头 + 浏览器同源标记；装了 `dsh-remote-web-ui` 时额外放行有效配对 cookie。

### 5.3 冲突与更新策略

| 场景 | 行为 |
|------|------|
| 目标名已存在，非本插件安装 | 409 + 提示，UI 二次确认后才带 `force` 重发 |
| 目标名已存在，且是市场安装的同一 id | 允许更新，覆盖并刷新 provenance |
| 目标名已存在，是市场安装的**不同** id | 409 + 明确提示来源不同 |
| 目标技能被本地手工编辑过（sha256 不匹配 provenance） | 更新前警告"本地已修改"，需勾选强制覆盖 |
| 卸载 | 仅允许卸载 provenance 记录在案、且未被手工修改的技能；移入 `.trash` 而非直接删除 |

## 6. 路由契约

全部路径为文档相对写法（客户端侧不带前导 `/`），host 侧注册带 `/` 前缀的 exact 路由。

**M1 已实现（8 条）**：

| 路由 | 方法 | 入参 | 说明 |
|------|------|------|------|
| `api/skills-hub/list` | GET | `?cwd=` | 本地技能分级列表（扫描 + 注册表合并） |
| `api/skills-hub/read` | GET | `?name=&path=` | 读单个技能可编辑字段与正文 |
| `api/skills-hub/set-enabled` | POST | `{name, path, enabled}` | 改写 frontmatter `disable-model-invocation` |
| `api/skills-hub/set-provider-enabled` | POST | `{name, provider, enabled}` | 插件提供技能的面板本地开关 |
| `api/skills-hub/create` | POST | `{root, name, description, whenToUse?, content, cwd}` | 新建技能 |
| `api/skills-hub/update` | POST | `{name, path, description, whenToUse?, content}` | 原地编辑（保留启用状态） |
| `api/skills-hub/delete` | POST | `{name, path}` | 移入 `.trash` |
| `api/skills-hub/preview` | GET | `?name=&cwd=` | 技能预览（**双源**：文件优先，回退技能注册表） |
| `api/skills-hub/health` | GET | — | 健康检查 + 能力上报 |

### 预览路由的双源设计（关键）

`preview` 只收**技能名**，不收路径。因为 bundled / runtime 注册的技能**磁盘上没有 SKILL.md**，
若只读文件，恰恰是用户最想看的那些技能预览不了。所以：

1. **先走文件**：最新扫描解析到 path → 读文件字节（写入路由信任的那份）。
2. **回退注册表**：`ctx.skills.get(name, {cwd})` 加载正文 —— 这是读 bundled/runtime 技能内容的**唯一**途径。
3. 响应带 `source: 'file' | 'registry'`，弹窗据此如实标注来源，不假装存在一个磁盘路径。

**例外**：文件存在时**绝不**回查注册表——文件才是用户能操作的对象。

### 预览内容不得包含 frontmatter（真实事故）

最初我把整份 `SKILL.md` 原文丢给 `MarkdownText`，这是错的：

- 官方渲染器**不支持 frontmatter**（`mdast-util-frontmatter` 未引入），但它支持 `thematicBreak` 与 `setext`。
- 于是结尾的 `---` 变成主题分隔线，**把上面的 `description:` 行变成 setext 二级标题**，整块 YAML 渲染成零散的 `key: value` 散文。

正确做法：**分开传**。正文走 `MarkdownText`，frontmatter 字段（name / description / whenToUse / 可调用性）
由 host 单独返回、弹窗用定义列表呈现。已在 `tests/m1-host.mjs` 加断言：
`markdown` 既不能以 `---` 开头，也不能出现 `^name:` 行。


**M2-M4 规划**：

| 路由 | 方法 | 入参 | 说明 |
|------|------|------|------|
| `api/skills-hub/market/search` | GET | `?q=&source=&limit=&cwd=` | 市场检索（多源聚合去重） |
| `api/skills-hub/market/detail` | GET | `?id=` | 技能详情 + SKILL.md 预览 |
| `api/skills-hub/market/sources` | GET | — | 可用源清单与可用性探测结果 |
| `api/skills-hub/market/install` | POST | `{id, target, cwd?, force?}` | 一键安装 |
| `api/skills-hub/market/installed` | GET | — | 已安装（含 provenance）清单 |
| `api/skills-hub/market/check-update` | POST | `{id}` | 比对远端 ref/sha256，报告是否有更新 |
| `api/skills-hub/market/uninstall` | POST | `{id, purge?}` | 卸载（移入 .trash） |
| `api/skills-hub/import/local` | POST | `{path, target, cwd?}` | 本地目录/压缩包导入 |

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| SDK cohort 升级导致插槽/服务签名变化 | 面板挂不上或路由注册失败 | 全程 `ctx.slots.inject` 条件注册；注册失败只 `console.warn` 不抛出（绝不能把整个 GUI 拖崩）；`dsh.engines.dsh` 声明下限 |
| `skills.sh` 接口变更或无公开文档 | 主搜索源失效 | 适配器隔离 + `registry` 自定义清单源兜底 + 明确的源可用性上报（`market/sources`） |
| GitHub 直连在国内不可用 | 安装失败 | 加速节点降级链（已实测 6 个可用节点）+ 用户可配置 |
| 恶意/畸形技能清单 | 任意路径写入、磁盘耗尽 | 客户端不发 URL；路径白名单；文件数与大小上限；硬超时；原子落盘 |
| 覆盖用户同名技能 | 数据丢失 | 非本插件来源一律 409，需显式 force；卸载/更新只碰 provenance 在案且未改动的项；删除走 `.trash` |
| Windows 下 rename 受句柄占用失败 | 安装偶发失败 | 参考 `dsh-market` 做法：短暂自旋后重试一次 |
| 与 skill-explorer 同时安装 | 面板/路由冲突 | 独立 id（`skills-hub`）、独立 key、独立路由前缀，二者可共存 |

**M0 的冒烟测试实际断言了以下合约**（这些是最容易在运行时静默失败的点）：

1. 客户端 bundle 以 `window.__ModuleLoader__.load({ id, factory })` 注册，且 id 精确等于包名；
2. factory 通过**注入的** `require` 解析 `react` / `react/jsx-runtime`，不依赖全局；
3. 不请求任何平台模块表之外的模块（否则运行时会抛「无法解析的 require」）；
4. 客户端导出 `apply` 与 `inject = ['slots','locale','layout']`；
5. host 导出 `apply` / `name = 'skills-hub'` / `inject = ['webServer','skills','sessions']`；
6. 每个声明的路由都在 `/api/skills-hub` 命名空间内；
7. `apply` 恰好注册一条 exact 路由；`config.enabled === false` 时不注册任何路由。

**验证过 `webServer` / `skills` / `sessions` 三个 host 服务名都真实存在**——这点很关键：cordis 的 `inject` 若引用不存在的服务会永久等待，插件会静默永不挂载。

> **需要用户重启 DSH 服务后生效**：`cordis.patch.yml` 的 bundle 行在服务启动时写入 `cordis.yml`。
> 本会话未重启正在运行的服务（`127.0.0.1:19387`，PID 10284，启动于 18:52），符合「不得中断运行中的 DSH 服务」的规则。

**实测补充**：用户重启后侧边栏入口与三页签面板均正常显示（见用户提供的截图）。
另经插件清单核对，`include:skills-hub` 的 `fiberPhase` 已是 `active`，说明插件管理器对该行做了**热挂载**，
不必然需要完整重启——但 `cordis.yml` 的持久行仍以服务启动时写入为准。

### M0 遗留缺陷的修复（已发现并修正）

M0 的 `panel.module.css` 用了 **3 个并不存在的主题 token**：`--dsw-alias-bg-primary`、
`--dsw-alias-border-secondary`、`--dsw-font-family-base`。

**这是静默失败**：CSS 自定义属性未定义时 `var()` 解析为空，整条声明被丢弃，**不报错**。
所以面板看起来「正常」，实际上没有背景色、没有边框、字体也没生效。

修复方式不是改对了事，而是补上守卫 `tests/theme-tokens.mjs`：

- 基准真相取自 **`app.asar`**（真正的主题样式表在应用打包内）。asar 逐字存储，可按字节块整体扫描；
  实测取出 **432 个** token 名。
- 逐个校验本包引用的每个 token（当前 17 个）；未定义即失败并列出出处文件。
- 带**负向控制**：把 `--dsw-alias-bg-base` 故意改回 `--dsw-alias-bg-primary`，守卫必须失败——实测确实捕获。

> 教训：**新增主题 token 前必须对照 shipped CSS 核验**。可用清单见 §7.3。
